The Swarms framework provides powerful real-time streaming capabilities for agents, allowing you to see responses being generated token by token as they're produced by the language model. This creates a more engaging and interactive experience, especially useful for long-form content generation, debugging, or when you want to provide immediate feedback to users.

## Installation

Install the swarms package using pip:

```bash
pip install -U swarms
```

## Basic Setup

1. First, set up your environment variables:

```python
WORKSPACE_DIR="agent_workspace"
OPENAI_API_KEY=""
```

## Step by Step

- Install and put your keys in `.env`

- Turn on streaming in `Agent()` with `streaming_on=True`

- `print_on=True` (the default) renders the tokens in a live panel; `print_on=False` streams silently and only returns the final text

## Code

```python
from swarms import Agent

agent = Agent(
    agent_name="StoryAgent",
    model_name="gpt-5.4",
    streaming_on=True,
    max_loops=1,
    print_on=True,
)

# Tokens render in a live panel as they arrive
response = agent.run("Tell me a detailed story about humanity colonizing the stars")
print(response)
```

## Send tokens to your own function

`streaming_callback` receives each token as a string. It only fires on streamed calls, so keep `streaming_on=True`:

```python
from swarms import Agent


def on_token(token: str) -> None:
    print(token, end="", flush=True)


agent = Agent(
    agent_name="StoryAgent",
    model_name="gpt-5.4",
    streaming_on=True,
    streaming_callback=on_token,
    max_loops=1,
)

response = agent.run("Tell me a short story about a lighthouse keeper")
```

## Iterate over tokens

`run_stream()` yields tokens as a generator, and `arun_stream()` is its async version. Both turn streaming on for the call, so you do not need `streaming_on=True`:

```python
from swarms import Agent

agent = Agent(agent_name="StoryAgent", model_name="gpt-5.4", max_loops=1)

for token in agent.run_stream("Tell me a short story about a lighthouse keeper"):
    print(token, end="", flush=True)

# Streamed calls are counted once the stream is consumed
print("\n", agent.usage)
```

`run_stream()` and `arun_stream()` run the agent through `run()` on a background thread. With `max_loops="auto"` they enter the autonomous loop, and tokens from every LLM turn, including turns that follow tool calls, come through the same stream. Exceptions raised in the run are re-raised once the stream ends.

## Typed stream events

By default, `run_stream()` and `arun_stream()` yield plain strings with `[thinking]` and `[tool call]` markers. When you need structured access to token types without parsing marker strings, pass `events=True`. Callers receive `StreamEvent` objects (exported directly from `swarms`) with a `kind` attribute and raw token `text`:

```python
from swarms import Agent, StreamEvent

agent = Agent(
    agent_name="StoryAgent",
    model_name="gpt-5.4",
    max_loops=1,
)

final_result = None
for event in agent.run_stream(
    "Tell me a short story about a lighthouse keeper",
    events=True,
):
    if event.kind == "reasoning":
        print(f"[thinking] {event.text}", end="", flush=True)
    elif event.kind == "content":
        print(event.text, end="", flush=True)
    elif event.kind == "tool_call":
        print(f"[tool call] {event.text}", end="", flush=True)
    elif event.kind == "final":
        final_result = event.text

print("\n\nCompleted response:\n", final_result)
```

The same `events=True` argument works on `arun_stream()`:

```python
import asyncio
from swarms import Agent

agent = Agent(agent_name="StoryAgent", model_name="gpt-5.4", max_loops=1)

async def main():
    async for event in agent.arun_stream("Tell me a short story", events=True):
        if event.kind == "content":
            print(event.text, end="", flush=True)
        elif event.kind == "final":
            print("\nDone:", event.text)

asyncio.run(main())
```

### Event kinds

| `kind` | Description | `event.text` |
|---|---|---|
| `content` | Text fragments that concatenate into the assistant's reply. Side calls such as the tool summary also arrive as `content` events. | Raw fragment string without extra section markers. |
| `reasoning` | Chain-of-thought tokens from reasoning models. | Raw reasoning token string without the `[thinking]` banner. |
| `tool_call` | Tool invocation descriptors and arguments. | Raw tool call signature and arguments without `[tool call]` headers. |
| `final` | Produced exactly once at the end of the stream. | The complete return value of `run()`, preserving any formatted output structure. |

Because `content` fragments join back into the reply text and side calls such as the tool summary also arrive as `content` events, always read the run's final result from the `final` event rather than accumulating fragments.

Without `events=True`, both `run_stream()` and `arun_stream()` keep the default plain string stream with `[thinking]` and `[tool call]` markers.
